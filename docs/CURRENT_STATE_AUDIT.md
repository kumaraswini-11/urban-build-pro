Related documents: [DEPENDENCY_AUDIT](DEPENDENCY_AUDIT.md) · [TARGET_ARCHITECTURE](TARGET_ARCHITECTURE.md) · [MODERNIZATION_DECISION](MODERNIZATION_DECISION.md) · [IMPLEMENTATION_ROADMAP](IMPLEMENTATION_ROADMAP.md) · [ENGINEERING_STANDARDS](ENGINEERING_STANDARDS.md)

## How this audit was done

- Every source and config file was read.
- Baseline checks were run: `eslint`, `tsc --noEmit`, `prettier --check`, `next build` (with and without `.env`), and `bun audit`.
- The production build was served locally and driven with Playwright (Chromium) at 1440, 1280, 768, 390 and 320 px. This covered full-page screenshots, interaction checks, a keyboard Tab walk, reduced-motion and no-JS rendering, and axe-core WCAG 2.2 AA scans.
- Two independent reviewers then tried to refute every finding.
  - Findings below are **confirmed** unless marked _partially confirmed_.
  - Priorities reflect the reviewers' calibration.
- Facts about Next.js 16, Tailwind 4, Motion and WCAG were checked against the official documentation (sources are in the other documents).

Not measured: real-network Core Web Vitals. Local LCP on localhost was 0.36–0.52 s, which is **not** representative because there was no throttling. Field or throttled Lighthouse numbers should be collected after deployment.

## 1. What the application is

A **single-page marketing website** for a construction firm, built with the Next.js App Router. Its one business goal is to present the firm and **capture quote requests (leads)**.

It is not a data-heavy application. It has no authentication, no backend, no database, no API routes, no file management and no multi-page routing. Sections of the enterprise-app brief that do not apply (tables, bulk actions, file and folder workflows, authorization) are deliberately out of scope here.

### Structure

```
app/          layout.tsx, page.tsx (composes 12 sections), not-found.tsx, global-error.tsx, robots.ts, sitemap.ts, globals.css
components/   ui/ (shadcn) · sections/ (12 page sections) · brand-ish leaves (logo, pretitle, construction-button, socials, slider, faq-item, nav-*)

public/       assets/images/** (17 MB, several unused or mis-encoded)
```

### Strengths worth keeping

- **Modern foundation.** Next 16 App Router, React 19 with the Compiler, Tailwind 4 CSS-first tokens, TypeScript strict and shadcn/ui. This is the same stack a greenfield build would pick (see TARGET_ARCHITECTURE).
- **Clean baseline.** `eslint` passes with 0 problems, `tsc --noEmit` passes, `prettier --check` passes, and the build succeeds when the environment variable is set.
- **Content is separated from presentation** in `lib/constants.ts` and `lib/types.ts`.
- **Coherent visual identity.** The yellow and black industrial look (OKLCH primary, radius 0, DM Sans + Barlow) is visually consistent in screenshots and reads as one product.
- **Small, readable codebase.** Short components, consistent naming and a sensible import-order rule.
- **Good basics already in place.** `next/image` on most images, `next/font`, a Radix Sheet with a correct focus trap and focus return, alt text on most images, and `rel="noopener noreferrer"` on external links.
- **Layout stability.** CLS measured at 0.001–0.002.

## 2. Findings

Priority scale:

- **P0:** security, data loss or launch blocker.
- **P1:** broken core workflow, serious accessibility or performance problem.
- **P2:** maintainability, moderate UX or accessibility issue, incomplete states.
- **P3:** polish.

## 4. Open questions for the product owner

1. **Where should leads go?** Email inbox, CRM (e.g. HubSpot), or both? Which email provider (Resend, Postmark, SES)? Is storing leads as a backup acceptable (privacy policy needed)?
2. **Hosting target?** Vercel, a Node server, or Windows hosting? This affects S1 urgency, image optimization and headers.
3. **Is a newsletter actually wanted?** If not, remove the form.
4. **Is dark mode a requirement?** If not, delete it and `next-themes`.
5. **Will the site grow beyond one page** (service pages, case studies, CMS, i18n)? This is the main trigger for revisiting the architecture (see MODERNIZATION_DECISION).
6. **Real content.** Phone, email, address, social URLs, CEO name and signature, project case-study links, testimonials with permission, and a high-resolution avatar.
